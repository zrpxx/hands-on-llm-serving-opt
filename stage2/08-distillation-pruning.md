# 2.8 蒸馏与剪枝

> 对应原书第 6 章 *Distillation*、*Pruning*。SparseGPT、Wanda 等剪枝算法是书外内容。

量化保留了模型的结构，只降低每个数的精度。模型压缩还有另外两条路：**蒸馏**训练一个更小的新模型来模仿原模型，**剪枝**直接去掉原模型中不重要的部分。原书认为蒸馏的潜力最大，剪枝在生产中用得最少。这一节介绍两者的原理、现状，以及它们和服务优化的关系。

## 1. 蒸馏

### 1.1 基本做法

蒸馏中，原来的大模型叫**教师**，要训练的小模型叫**学生**。学生的训练目标可以有几种：

- **软标签**。让学生在每个位置输出的概率分布接近教师的分布，通常最小化两者的 KL 散度。Hinton 等人在 2015 年提出这种做法时，还用温度 $T$ 把两边的分布拉平，让概率较小的那些 token 也能传递信息。教师的分布里有比"正确答案"多得多的信息，比如哪些词是合理的备选。
- **硬标签，也就是教师生成的文本**。用教师生成大量回答，学生在这些回答上做普通的监督微调。这种做法叫序列级蒸馏，只需要教师的输出文本。

> [!NOTE]
> 原书说，蒸馏需要完全访问教师模型，仅通过 API 获取输出 token 是不够的。这只适用于软标签的蒸馏。DeepSeek-R1 的蒸馏模型恰恰是用硬标签得到的：用 R1 生成约 80 万条样本，在 Qwen 和 Llama 的基座模型上做监督微调，没有用到教师的概率分布，也没有做强化学习。

### 1.2 例子

原书以 DeepSeek-R1 为例。R1 是一个 6710 亿参数的 MoE 模型，DeepSeek 同时发布了 1.5B 到 70B 的六个蒸馏模型。原书表 6-6 比较了 R1 和其中最大的 DeepSeek-R1-Distill-Llama-70B：

| 评测 | DeepSeek-R1 | R1-Distill-Llama-70B |
|---|---|---|
| MATH-500 pass@1 | 97.3 | 94.5 |
| GPQA Diamond pass@1 | 71.5 | 65.2 |
| LiveCodeBench pass@1 | 65.9 | 57.5 |

从服务的角度，70B 的稠密模型比 R1 小将近 10 倍，一台 8 卡的机器上部署 R1 的资源，可以运行多个 70B 的副本。代价是精度有明显下降，尤其是代码。

另一个例子是 Qwen3。它的小尺寸模型（0.6B 到 14B，以及 30B-A3B）是从旗舰模型蒸馏得到的，同时用了教师生成的数据和教师的概率分布。Qwen 的技术报告称，这比对每个小模型单独做完整的后训练省了约 90% 的 GPU 时间。这说明蒸馏已经是模型发布方的标准做法，只不过大多数时候由他们来完成。

### 1.3 量化还是蒸馏

原书表 6-7 的比较：

| | 量化 | 蒸馏 |
|---|---|---|
| 精度损失 | 小，通常在 3% 以内 | 比量化大得多 |
| 速度提升 | 1.5 到 3 倍 | 大得多，取决于学生模型的大小 |
| 难度 | PTQ 很容易，只需要原模型的权重 | 没有现成的蒸馏模型时很难，训练成本可能达到原模型的 10% |

原书的建议是先从简单、便宜的办法开始：如果有现成的蒸馏模型，先评测它是否满足精度要求，满足就用它，还可以在它的基础上再做量化；没有现成的蒸馏模型时（实际中大多如此），先做量化。

还有一种和服务直接相关的蒸馏：为投机解码训练草稿模型。EAGLE 等方法训练一个很小的草稿头来预测目标模型的下一个 token，本质上也是让小模型模仿大模型的输出分布。3.4、3.5 节会详细讨论。

## 2. 剪枝

### 2.1 三种粒度

剪枝的出发点是大模型普遍参数冗余，去掉一部分权重影响不大。按去掉的单位，可以分成三种：

| 粒度 | 去掉什么 | 能否在 GPU 上加速 | 例子 |
|---|---|---|---|
| 非结构化 | 任意位置的单个权重 | 很难。稀疏度要很高才有收益，GPU 的稠密矩阵乘法太快了 | SparseGPT、Wanda 的 50% 稀疏 |
| 半结构化（N:M） | 每 M 个连续权重中去掉 M−N 个 | 能。2:4 有专门的硬件支持 | Sparse Llama 3.1 |
| 结构化 | 整个注意力头、FFN 的通道、整层 | 能，剪完就是一个更小的稠密模型 | NVIDIA Minitron |

### 2.2 2:4 稀疏

2:4 稀疏要求每 4 个连续的权重中至少有 2 个是零。从 Ampere 开始，NVIDIA 的 Tensor Core 支持这种格式：矩阵只存一半的非零值，外加每个值 2 位的位置索引，计算时硬件按索引取出对应的激活，理论上矩阵乘法的速度翻倍。

剪掉哪两个，是剪枝算法要回答的问题。最直接的是保留绝对值大的；Wanda 则和 AWQ 的思路一样，把输入的幅度考虑进来，按 $|W_{ij}| \cdot \|X_j\|$ 打分。下面的组件比较了这几种准则。

SparseGPT 更进一步，和 GPTQ 一样利用 $H = 2XX^\top$ 的信息，在剪掉一个权重之后调整同一行中还没处理的权重，补偿剪枝带来的误差。它和 GPTQ 是同一批作者，算法框架几乎相同，只是把"量化到最近的等级"换成了"置零"。

在 Llama-2-7B 上，Wanda 的作者报告的 WikiText 困惑度是：原模型 5.12；2:4 稀疏时，按权重大小剪枝 54.59，SparseGPT 10.17，Wanda 11.02。一次性剪掉一半权重后，即使最好的方法，困惑度也接近翻倍。所以实用的 2:4 模型都需要在剪枝之后继续训练。

原书提到的 Sparse Llama 3.1 8B 就是这样做的：Neural Magic 先用 SparseGPT 剪成 2:4，再用大量数据继续训练。他们报告的结果是在 Open LLM Leaderboard v1 上恢复了 98% 的精度，在 vLLM 中仅靠稀疏就带来最多 30% 的吞吐提升和 1.8 倍的延迟降低；再结合 4 位量化和 Sparse-Marlin kernel，加速 1.4 到 4.9 倍。

> [!NOTE]
> 原书把 Sparse Llama 的延迟收益写成"降低 20%"，与 Neural Magic 公布的"1.8 倍"不一致。另外，原书说 50% 的稀疏"可以直接让矩阵乘法的速度翻倍"，这是 Tensor Core 的理论峰值。实际的端到端收益小得多：decode 时瓶颈是带宽，2:4 只省下约 44% 的权重字节（见组件中的存储计算）；注意力、通信等部分也不受影响。

### 2.3 结构化剪枝

结构化剪枝直接让模型变小：去掉一部分注意力头、FFN 的中间通道，或者整层。剪完之后是一个普通的稠密模型，不需要任何特殊的 kernel，所有引擎都能直接运行。但一次去掉的单位越大，精度损失越大，几乎一定要配合蒸馏来恢复。

NVIDIA 的 Minitron 是这种做法的代表：从 Nemotron-4 15B 出发，按重要性剪掉宽度（头、通道）或深度（层），再用原模型作为教师做蒸馏，得到 8B 和 4B 的模型。论文报告，这样得到一个小模型所需的训练数据比从头训练少了几十倍。之后他们用同样的方法从 Llama-3.1-8B 得到了 Llama-3.1-Minitron-4B。剪枝和蒸馏在这里是结合使用的。

### 2.4 现状

原书写作时（2025 年中）认为剪枝是三种压缩手段中最不常用的。到现在情况没有根本变化：

- 非结构化稀疏在 GPU 上基本没有加速效果，主要用于研究；
- 2:4 稀疏有硬件支持，vLLM 也能运行，但需要剪枝后再训练，现成的模型很少；
- 结构化剪枝加蒸馏是一种得到小模型的有效方法，但这是模型发布方做的事，对部署者来说，拿到的就是一个普通的小模型。

## 3. 实验

`tools/prune_24.py` 对小模型的所有线性层做 2:4 剪枝，不做任何补偿，比较按权重大小和 Wanda 两种准则：

```bash
cd code/project2
python tools/prune_24.py --model /tmp/tiny-lm --data /tmp/qcorpus
```

结果：

| | 困惑度 |
|---|---|
| 原模型 | 37.98 |
| 2:4，按权重大小 | 42.72 |
| 2:4，Wanda | 44.40 |

两个现象都和大模型不同。第一，损失比 Llama-2-7B 小得多，说明这个小模型相对它的训练数据有很多冗余的参数。第二，Wanda 反而更差。Wanda 的优势来自激活中的离群特征：大通道上的权重被保留。这个小模型没有离群特征，各通道的幅度相近，按 $\|X_j\|$ 加权只是引入了噪声。这又一次说明，压缩方法的效果要在目标模型上验证。
