# 3.4 投机解码原理

> 对应原书第 7 章 *Speculative Decoding* 的 *Detailed Steps*。拒绝采样的证明和加速比的推导是书外内容，来自 Leviathan 等人和 Chen 等人的两篇原始论文。

自回归生成每一步只产生一个 token，而 decode 的每一步都受限于显存带宽：不管这一步处理一个 token 还是五个，读权重的时间几乎一样（0.7 节）。投机解码利用了这一点：先用一个便宜的方法猜出后面几个 token，再让目标模型用一次前向同时验证它们。猜对了，一次前向就前进了好几个 token。

原书说它能让 ITL 降低两到三倍，特别适合输出长、推理密集的生成。这一节讲清楚它为什么不会改变输出，以及能快多少。

## 1. 一轮投机解码

原书图 7-1 把一轮分成四步：

1. **起草**。草稿模型以当前序列为输入，自回归地生成 $K$ 个 token $x_1, \dots, x_K$，并记下每一步的概率分布 $q_1, \dots, q_K$。
2. **验证**。目标模型对"当前序列 + $K$ 个草稿"做一次前向，得到 $K+1$ 个位置的分布 $p_1, \dots, p_{K+1}$。第 $i$ 个分布是目标模型在看到前 $i-1$ 个草稿之后，对下一个 token 的预测。
3. **接受或拒绝**。从 $x_1$ 开始逐个检查，第一个被拒绝的位置之后的草稿全部丢弃，因为它们的前提已经不成立了。
4. **补一个 token**。在被拒绝的位置，由目标模型重新给出一个 token；如果 $K$ 个都被接受，还可以用 $p_{K+1}$ 再采样一个。所以每一轮至少产出 1 个 token，最多 $K+1$ 个。

第 2 步的代价和普通 decode 的一步差不多，因为在 batch 不大时，处理 $K+1$ 个 token 和处理 1 个 token 读的权重是一样的。

## 2. 为什么输出不变

### 2.1 贪心解码

贪心解码时，规则很简单：如果 $x_i$ 等于 $p_i$ 的 argmax，就接受，否则拒绝并换成 argmax。每个被接受的 token 都恰好是目标模型自己会选的，所以输出和不用投机解码完全相同。

### 2.2 采样

采样时，目标是让每个输出 token 的**分布**与直接从 $p$ 采样相同。Leviathan 等人和 Chen 等人给出的方法是**拒绝采样**：

- 以 $\min\left(1, \dfrac{p(x)}{q(x)}\right)$ 的概率接受草稿 token $x$；
- 如果拒绝，从修正后的分布中采样一个 token：

$$
p'(x) = \frac{\max\big(0,\ p(x) - q(x)\big)}{\sum_{x'} \max\big(0,\ p(x') - q(x')\big)}
$$

直觉是：草稿模型给某个 token 的概率比目标模型高时，按比例拒绝掉多出来的部分；比目标模型低时，一定接受，欠缺的部分由拒绝后的重新采样来补。

证明只需要几行。记接受的总概率为 $\beta = \sum_x \min(p(x), q(x))$。最终输出 $x$ 的概率是"草稿恰好是 $x$ 并被接受"加上"被拒绝后重新采样到 $x$"：

$$
q(x) \min\left(1, \frac{p(x)}{q(x)}\right) + (1 - \beta)\, p'(x) = \min(p(x), q(x)) + \big(p(x) - \min(p(x), q(x))\big) = p(x)
$$

第二项化简用到了 $\sum_x \max(0, p(x) - q(x)) = 1 - \beta$。

> [!NOTE]
> 原书说，拒绝后目标模型"从排除了被拒绝 token 的修正分布中"重新采样。准确地说，修正分布是 $\max(0, p - q)$ 归一化后的结果，它排除的是所有 $q \geq p$ 的 token，而不只是被拒绝的那一个。被拒绝的 token 一定满足 $q > p$，所以它确实被排除了，但其他 token 的概率也被重新分配了。只排除被拒绝的那一个，得到的分布就不再等于 $p$。

$\beta$ 也就是**接受率**，它等于 $1$ 减去 $p$ 与 $q$ 的总变差距离。草稿模型和目标模型的分布越接近，接受率越高。

原书还举了一个例子：目标模型认为 States 的概率是 0.4，草稿模型认为是 0.6，接受的概率就是 $0.4 / 0.6 \approx 0.67$。

### 2.3 数值上的一致

"输出不变"是在精确计算的意义下说的。实际中，目标模型一次处理 $K+1$ 个 token，和一次处理 1 个 token，用到的 kernel 和累加顺序可能不同，浮点误差也就不同，贪心解码的结果偶尔会在某个位置出现分歧。这不是投机解码的问题，而是浮点计算与 batch 形状有关的普遍现象，6.7 节会专门讨论。

## 3. 能快多少

假设每个草稿 token 被接受的概率都是 $\alpha$，而且相互独立。一轮中前 $i$ 个草稿都被接受的概率是 $\alpha^i$，所以一轮的期望产出是：

$$
E[\text{产出}] = 1 + \alpha + \alpha^2 + \dots + \alpha^K = \frac{1 - \alpha^{K+1}}{1 - \alpha}
$$

设目标模型一次前向的耗时为 1，草稿模型一次前向为 $c$，一轮的耗时是 $1 + Kc$。加速比就是：

$$
\text{加速比} = \frac{1 - \alpha^{K+1}}{(1 - \alpha)(1 + Kc)}
$$

这个公式说明了几件事：

- $\alpha$ 是最关键的因素。$\alpha = 0.8$、$K = 4$、$c = 0.05$ 时加速比约 2.8；$\alpha$ 降到 0.5，就只有约 1.6。
- $K$ 不是越大越好。第 $i$ 个草稿被接受的概率是 $\alpha^i$，越往后越低，开销却是同样的 $c$。存在一个最优的 $K$。
- $c$ 越小，能承受的 $K$ 越大。n-gram 的 $c$ 几乎为零，所以即使接受率不高也有收益，这正是原书推荐先试 n-gram 的原因。

这个模型忽略了两个因素，实际中都很重要：验证 $K+1$ 个 token 并不总是和 1 个 token 一样快，batch 大时尤其如此；接受率也不是常数，它随位置、内容变化。3.5 节会讨论这些。

## 4. 实验：在 CPU 上验证

项目 3 的第 6 步实现了拒绝采样、贪心验证和 n-gram 提议。`spec_demo.py` 用两个在同一份语料上训练的小模型做实验：目标模型 4 层、隐藏维度 256，约 370 万参数；草稿模型 1 层、隐藏维度 128，约 50 万参数。两个模型共用一个分词器。

```bash
cd code/project3
python ../project2/tools/train_tiny_lm.py --data ../project2/data --out /tmp/draft-lm \
    --tokenizer /tmp/tiny-lm --layers 1 --hidden 128
FORGE_IMPL=solution python spec_demo.py --target /tmp/tiny-lm --draft /tmp/draft-lm --data ../project2/data
```

贪心解码，6 个 prompt，每个生成 48 个 token。这台机器上草稿一次前向的耗时约为目标模型的 0.22：

| 方法 | K | 接受率 | 每次目标前向产出 | 估算加速比 | 第 1～4 个草稿被接受的比例 |
|---|---|---|---|---|---|
| 草稿模型 | 1 | 0.49 | 1.48 | 1.22 | 0.49 |
| 草稿模型 | 2 | 0.38 | 1.77 | 1.23 | 0.48、0.28 |
| 草稿模型 | 4 | 0.23 | 1.91 | 1.02 | 0.48、0.27、0.12、0.05 |
| 草稿模型 | 6 | 0.17 | 1.97 | 0.85 | 0.49、0.28、0.12、0.05 |
| n-gram | 4 | 0.51 | 1.30 | 1.30 | 0.10、0.09、0.07、0.05 |

几点观察：

- 贪心模式下，脚本会检查每个输出都与目标模型自己生成的结果完全一致，这是投机解码正确性的底线。
- 第 $i$ 个草稿被接受的比例约为 0.49、0.28、0.12、0.05，与 $\alpha^i$（0.49、0.24、0.12、0.06）很接近，说明"独立、同一接受率"的假设在这里大致成立。
- 草稿模型的接受率不高，$c$ 又比较大（CPU 上小模型的开销不能忽略），最优的 $K$ 只有 1 到 2。$K = 6$ 时已经比不用投机解码更慢。
- n-gram 的 $c$ 几乎为零，虽然只在少数位置能找到匹配，加速比反而最高。它的匹配主要来自贪心解码时小模型生成的重复片段。用 `--temperature 1.0` 采样时，生成的文本很少重复，n-gram 几乎提不出草稿。

"每次目标前向产出"是与硬件无关的指标，"估算加速比"用的是 CPU 上测得的 $c$。在 GPU 上，decode 受限于带宽的程度更高，验证几个 token 的额外开销更小，同样的接受率能换来更好的加速。
